# 前端项目自动化部署指南

## 📋 概述

本文档介绍如何使用 GitHub Actions 实现前端项目的自动化部署，采用传统服务器部署方案（非容器化），通过 SSH 和 rsync 将构建产物自动部署到生产服务器。

### 部署方案对比

| 维度           | Docker 部署               | 传统部署（本方案）          |
| -------------- | ------------------------- | --------------------------- |
| **部署速度**   | ⭐⭐⭐⭐⭐ 快（镜像拉取） | ⭐⭐⭐⭐ 快（文件同步）     |
| **环境一致性** | ⭐⭐⭐⭐⭐ 高             | ⭐⭐⭐ 中等                 |
| **运维复杂度** | ⭐⭐⭐⭐ 中等（容器管理） | ⭐⭐⭐⭐⭐ 简单（文件管理） |
| **资源占用**   | ⭐⭐⭐ 中等（容器运行时） | ⭐⭐⭐⭐⭐ 低（直接运行）   |
| **学习成本**   | ⭐⭐⭐ 中等               | ⭐⭐⭐⭐⭐ 低               |
| **CI/CD 集成** | ⭐⭐⭐⭐⭐ 优秀           | ⭐⭐⭐⭐⭐ 优秀             |
| **扩展性**     | ⭐⭐⭐⭐⭐ 优秀           | ⭐⭐⭐ 一般                 |

### 为什么选择传统部署？

1. **简单直接**：无需 Docker 知识，直接部署静态文件
2. **资源占用低**：无容器运行时开销，适合资源受限场景
3. **调试方便**：直接访问服务器文件，便于排查问题
4. **性能优秀**：直接使用系统 Nginx，性能略优于容器化
5. **自动化支持**：通过 GitHub Actions 实现完全自动化

## 🚀 快速开始

### 前置要求

#### 服务器要求

- Linux 服务器（推荐 Ubuntu 20.04+ 或 CentOS 7+）
- Nginx 已安装并运行
- SSH 服务已启用
- 足够的磁盘空间（建议至少 5GB）

#### 本地要求

- Git 仓库访问权限
- GitHub 仓库管理员权限（用于配置 Secrets）

## 📝 配置步骤

### 步骤 1: 服务器端准备

#### 1.1 创建部署目录

```bash
# 创建部署目录
sudo mkdir -p /var/www/qm-photo-admin

# 设置目录权限
sudo chown -R www-data:www-data /var/www/qm-photo-admin
sudo chmod -R 755 /var/www/qm-photo-admin
```

#### 1.2 配置 SSH 密钥认证

**方式一：使用 root 用户（简单但不推荐）**

```bash
# 在服务器上创建 .ssh 目录
sudo mkdir -p ~/.ssh
sudo chmod 700 ~/.ssh

# 编辑 authorized_keys 文件
sudo nano ~/.ssh/authorized_keys
# 将 GitHub Actions 使用的公钥粘贴进去

sudo chmod 600 ~/.ssh/authorized_keys
```

**方式二：创建专用部署用户（推荐）**

```bash
# 创建部署用户
sudo useradd -m -s /bin/bash deploy

# 创建 SSH 目录
sudo mkdir -p /home/deploy/.ssh
sudo chmod 700 /home/deploy/.ssh

# 添加公钥
sudo nano /home/deploy/.ssh/authorized_keys
# 粘贴公钥内容

sudo chmod 600 /home/deploy/.ssh/authorized_keys
sudo chown -R deploy:deploy /home/deploy/.ssh

# 如果需要 sudo 权限（用于重启 Nginx）
sudo visudo
# 添加以下行：
# deploy ALL=(ALL) NOPASSWD: /usr/sbin/nginx, /bin/systemctl reload nginx
```

#### 1.3 生成 SSH 密钥对

在本地生成 SSH 密钥对：

```bash
# 生成密钥对（如果还没有）
ssh-keygen -t ed25519 -C "github-actions-deploy" -f ~/.ssh/github_actions_deploy

# 查看公钥（需要添加到服务器的 authorized_keys）
cat ~/.ssh/github_actions_deploy.pub

# 查看私钥（需要添加到 GitHub Secrets）
cat ~/.ssh/github_actions_deploy
```

**重要提示**：

- **公钥**（`.pub` 文件）→ 添加到服务器的 `~/.ssh/authorized_keys`
- **私钥**（无 `.pub` 后缀）→ 添加到 GitHub Secrets 的 `SSH_PRIVATE_KEY`

#### 1.4 配置 Nginx

创建 Nginx 配置文件：

```bash
sudo nano /etc/nginx/sites-available/qm-photo-admin
```

配置文件内容：

```nginx
server {
    listen 80;
    server_name your-domain.com;  # 替换为你的域名或 IP
    root /var/www/qm-photo-admin;
    index index.html;

    # 日志配置
    access_log /var/log/nginx/qm-photo-admin-access.log;
    error_log /var/log/nginx/qm-photo-admin-error.log;

    # Gzip 压缩
    gzip on;
    gzip_vary on;
    gzip_min_length 1024;
    gzip_types text/plain text/css text/xml text/javascript
               application/x-javascript application/xml+rss
               application/json application/javascript;

    # 静态资源缓存（1年）
    location ~* \.(jpg|jpeg|png|gif|ico|css|js|svg|woff|woff2|ttf|eot)$ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    # API 代理到后端服务
    location /api {
        proxy_pass http://localhost:3008;  # 后端服务地址
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # 超时设置
        proxy_connect_timeout 60s;
        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
    }

    # Vue Router 历史模式支持
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 健康检查端点
    location /health {
        access_log off;
        return 200 "healthy\n";
        add_header Content-Type text/plain;
    }
}
```

启用配置：

```bash
# 创建符号链接
sudo ln -s /etc/nginx/sites-available/qm-photo-admin /etc/nginx/sites-enabled/

# 测试配置
sudo nginx -t

# 重启 Nginx
sudo systemctl restart nginx
```

### 步骤 2: GitHub 配置

#### 2.1 配置 GitHub Secrets

进入 GitHub 仓库 → Settings → Secrets and variables → Actions → New repository secret

添加以下 Secrets：

| Secret 名称 | 说明 | 示例值 |
| --- | --- | --- |
| `SSH_PRIVATE_KEY` | SSH 私钥（完整内容，包括 `-----BEGIN` 和 `-----END`） | `-----BEGIN OPENSSH PRIVATE KEY-----<br>...<br>-----END OPENSSH PRIVATE KEY-----` |
| `SSH_HOST` | 服务器 IP 地址或域名 | `123.456.789.0` 或 `server.example.com` |
| `SSH_USER` | SSH 用户名 | `root` 或 `deploy` |
| `DEPLOY_PATH` | 服务器部署路径 | `/var/www/qm-photo-admin` |
| `VITE_API_URL` | 生产环境 API 地址 | `https://api.yourdomain.com/api/v1` |
| `VITE_BASE_URL` | 应用基础路径 | `/` |

**配置 SSH_PRIVATE_KEY 的注意事项**：

1. 复制完整的私钥内容，包括：

   ```
   -----BEGIN OPENSSH PRIVATE KEY-----
   [密钥内容]
   -----END OPENSSH PRIVATE KEY-----
   ```

2. 如果私钥有密码保护，需要先移除密码：

   ```bash
   ssh-keygen -p -f ~/.ssh/github_actions_deploy
   # 输入旧密码，新密码留空
   ```

3. 确保私钥格式正确，每行末尾不要有多余的空格

#### 2.2 创建 GitHub Actions 工作流

在项目根目录创建 `.github/workflows/deploy.yml`：

```yaml
name: Build and Deploy Frontend

on:
  push:
    branches:
      - master
      - feat/deploy-prod
    paths:
      - '**'
      - '!.github/workflows/**'
  workflow_dispatch:
    inputs:
      environment:
        description: '部署环境'
        required: true
        default: 'production'
        type: choice
        options:
          - production
          - staging

env:
  NODE_VERSION: '20'
  PNPM_VERSION: '9'

jobs:
  build-and-deploy:
    name: Build and Deploy
    runs-on: ubuntu-latest
    timeout-minutes: 15

    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}

      - name: Setup pnpm
        uses: pnpm/action-setup@v3
        with:
          version: ${{ env.PNPM_VERSION }}

      - name: Get pnpm store directory
        shell: bash
        run: |
          echo "STORE_PATH=$(pnpm store path --silent)" >> $GITHUB_ENV

      - name: Setup pnpm cache
        uses: actions/cache@v4
        with:
          path: ${{ env.STORE_PATH }}
          key: ${{ runner.os }}-pnpm-store-${{ hashFiles('**/pnpm-lock.yaml') }}
          restore-keys: |
            ${{ runner.os }}-pnpm-store-

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Build project
        env:
          VITE_API_URL: ${{ secrets.VITE_API_URL }}
          VITE_BASE_URL: ${{ secrets.VITE_BASE_URL }}
          VITE_VERSION: ${{ github.sha }}
        run: pnpm run build

      - name: Create deployment archive
        run: |
          cd dist
          tar -czf ../deploy.tar.gz .
          cd ..
          echo "部署包大小:"
          ls -lh deploy.tar.gz

      - name: Setup SSH
        uses: webfactory/ssh-agent@v1
        with:
          ssh-private-key: ${{ secrets.SSH_PRIVATE_KEY }}

      - name: Add server to known hosts
        run: |
          mkdir -p ~/.ssh
          ssh-keyscan -H ${{ secrets.SSH_HOST }} >> ~/.ssh/known_hosts

      - name: Deploy to server
        env:
          SSH_HOST: ${{ secrets.SSH_HOST }}
          SSH_USER: ${{ secrets.SSH_USER }}
          DEPLOY_PATH: ${{ secrets.DEPLOY_PATH }}
        run: |
          echo "🚀 开始部署到服务器..."

          # 上传部署包
          scp deploy.tar.gz ${SSH_USER}@${SSH_HOST}:/tmp/deploy.tar.gz

          # 执行部署脚本
          ssh ${SSH_USER}@${SSH_HOST} << 'EOF'
            set -e
            
            DEPLOY_PATH="${DEPLOY_PATH}"
            BACKUP_DIR="/tmp/frontend-backup-$(date +%Y%m%d-%H%M%S)"
            
            echo "📦 备份当前版本..."
            if [ -d "$DEPLOY_PATH" ]; then
              mkdir -p "$BACKUP_DIR"
              cp -r "$DEPLOY_PATH"/* "$BACKUP_DIR/" 2>/dev/null || true
              echo "✅ 备份完成: $BACKUP_DIR"
            fi
            
            echo "📂 创建部署目录..."
            mkdir -p "$DEPLOY_PATH"
            
            echo "📥 解压部署包..."
            cd "$DEPLOY_PATH"
            tar -xzf /tmp/deploy.tar.gz
            rm -f /tmp/deploy.tar.gz
            
            echo "✅ 文件部署完成"
            
            # 设置文件权限
            chown -R www-data:www-data "$DEPLOY_PATH" || chown -R nginx:nginx "$DEPLOY_PATH" || true
            chmod -R 755 "$DEPLOY_PATH"
            
            echo "✅ 权限设置完成"
          EOF

          echo "✅ 部署完成！"

      - name: Reload Nginx (optional)
        if: success()
        env:
          SSH_HOST: ${{ secrets.SSH_HOST }}
          SSH_USER: ${{ secrets.SSH_USER }}
        run: |
          ssh ${SSH_USER}@${SSH_HOST} << 'EOF'
            # 测试 Nginx 配置
            if command -v nginx &> /dev/null; then
              if sudo nginx -t; then
                echo "🔄 重新加载 Nginx..."
                sudo nginx -s reload || sudo systemctl reload nginx || true
                echo "✅ Nginx 重新加载完成"
              else
                echo "⚠️ Nginx 配置测试失败，跳过重新加载"
              fi
            else
              echo "ℹ️ 未找到 Nginx，跳过重新加载"
            fi
          EOF
        continue-on-error: true

      - name: Deployment summary
        if: always()
        run: |
          echo "## 部署总结" >> $GITHUB_STEP_SUMMARY
          echo "" >> $GITHUB_STEP_SUMMARY
          echo "- **分支**: ${{ github.ref_name }}" >> $GITHUB_STEP_SUMMARY
          echo "- **提交**: ${{ github.sha }}" >> $GITHUB_STEP_SUMMARY
          echo "- **作者**: ${{ github.actor }}" >> $GITHUB_STEP_SUMMARY
          echo "- **时间**: $(date)" >> $GITHUB_STEP_SUMMARY
          echo "- **状态**: ${{ job.status }}" >> $GITHUB_STEP_SUMMARY
```

## 🎯 使用流程

### 自动部署

1. **推送代码到 master 分支**

   ```bash
   git add .
   git commit -m "feat: 新功能"
   git push origin master
   ```

2. **GitHub Actions 自动触发**
   - 进入 GitHub 仓库的 Actions 页面
   - 查看工作流执行状态
   - 等待部署完成（通常 3-5 分钟）

3. **验证部署**
   - 访问网站检查是否更新
   - 查看浏览器控制台是否有错误
   - 检查服务器日志：`tail -f /var/log/nginx/qm-photo-admin-error.log`

### 手动触发部署

如果需要手动触发部署：

1. 进入 GitHub 仓库 → Actions
2. 选择 "Build and Deploy Frontend" 工作流
3. 点击 "Run workflow"
4. 选择部署环境（production/staging）
5. 点击 "Run workflow" 按钮

## 🔍 故障排查

### 常见问题

#### 1. SSH 连接失败

**错误信息**：

```
Permission denied (publickey)
```

**解决方案**：

- 检查 SSH 私钥是否正确配置在 GitHub Secrets
- 确认公钥已添加到服务器的 `~/.ssh/authorized_keys`
- 检查服务器 SSH 服务是否运行：`sudo systemctl status ssh`
- 检查 SSH 用户是否有正确的权限

#### 2. 文件权限错误

**错误信息**：

```
chown: changing ownership of ...: Operation not permitted
```

**解决方案**：

- 确保部署用户有权限访问部署目录
- 如果使用非 root 用户，确保用户有 sudo 权限或目录权限正确
- 检查 SELinux 设置（如果启用）

#### 3. Nginx 配置错误

**错误信息**：

```
nginx: configuration file /etc/nginx/nginx.conf test failed
```

**解决方案**：

- 检查 Nginx 配置文件语法：`sudo nginx -t`
- 查看详细错误信息并修复
- 确保部署路径存在且可访问

#### 4. 构建失败

**错误信息**：

```
Error: VITE_API_URL is not defined
```

**解决方案**：

- 检查 GitHub Secrets 中是否配置了 `VITE_API_URL`
- 确认环境变量名称正确（区分大小写）
- 检查构建脚本中的环境变量使用

#### 5. 部署后页面空白

**可能原因**：

- API 地址配置错误
- 路由配置问题
- 静态资源路径错误

**解决方案**：

- 检查浏览器控制台错误信息
- 确认 `VITE_API_URL` 配置正确
- 检查 `VITE_BASE_URL` 是否匹配实际部署路径
- 查看 Nginx 错误日志：`sudo tail -f /var/log/nginx/qm-photo-admin-error.log`

### 查看部署日志

**GitHub Actions 日志**：

- 进入 GitHub 仓库 → Actions
- 点击对应的部署工作流
- 查看各步骤的详细日志

# Nginx 访问日志

## 🔄 回滚方案

### 自动回滚

如果部署失败，GitHub Actions 会自动停止，不会更新服务器文件。

### 手动回滚

如果需要回滚到之前的版本：

```bash
# 1. 查看备份目录
ls -lt /tmp/frontend-backup-*

# 2. 选择要回滚的版本（例如：frontend-backup-20231220-143000）
BACKUP_DIR="/tmp/frontend-backup-20231220-143000"
DEPLOY_PATH="/var/www/qm-photo-admin"

# 3. 备份当前版本（可选）
sudo cp -r "$DEPLOY_PATH" "/tmp/current-backup-$(date +%Y%m%d-%H%M%S)"

# 4. 恢复备份版本
sudo rm -rf "$DEPLOY_PATH"/*
sudo cp -r "$BACKUP_DIR"/* "$DEPLOY_PATH"/

# 5. 设置权限
sudo chown -R www-data:www-data "$DEPLOY_PATH"
sudo chmod -R 755 "$DEPLOY_PATH"

# 6. 重新加载 Nginx
sudo nginx -s reload
```

### 清理旧备份

定期清理旧备份以节省磁盘空间：

```bash
# 保留最近 5 个备份，删除其他
ls -dt /tmp/frontend-backup-* 2>/dev/null | tail -n +6 | xargs rm -rf
```

- 使用 GitHub Secrets 管理敏感信息
- 不同环境使用不同的 Secrets
- 定期轮换 SSH 密钥

### 3. 部署前检查

- 在本地测试构建：`pnpm run build`
- 检查构建产物大小是否合理
- 验证环境变量配置

### 4. 版本管理

- 使用 Git Tag 标记重要版本
- 保留部署历史记录
- 实现版本回滚机制

### 5. 安全建议

- 使用专用部署用户，避免使用 root
- 限制 SSH 访问 IP（如果可能）
- 定期更新服务器系统和软件
- 使用 HTTPS（配置 SSL 证书）

## ❓ 常见问题 FAQ

### Q: 部署需要多长时间？

A: 通常 3-5 分钟，取决于：

- 依赖安装时间（首次较慢，有缓存后较快）
- 构建时间（项目大小）
- 网络速度（上传文件到服务器）

### Q: 可以同时部署到多台服务器吗？

A: 可以，修改工作流添加多个部署步骤，或使用矩阵策略。

### Q: 如何跳过部署？

A: 在提交信息中添加 `[skip ci]` 或 `[skip deploy]`。

### Q: 部署失败会回滚吗？

A: 不会自动回滚，但不会更新服务器文件，保持当前版本不变。

### Q: 如何查看部署历史？

A: 在 GitHub Actions 页面查看所有工作流运行记录。
